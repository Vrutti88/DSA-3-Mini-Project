1. Trie (Prefix Tree) Architecture

A Trie is an $m$-ary tree where each node represents a character along a word path. Common prefixes share nodes from the root down, avoiding redundant storage.

Lookup Time: $O(P)$ where $P$ is prefix length, strictly independent of total dictionary size $N$.
Node Structure: Fixed 26-pointer array ($a-z$) yielding $O(1)$ child branch resolution with zero hash overhead.
Frequency Ranking: Terminal nodes store word occurrence frequency for $O(K \log K)$ sorting.

2D Levenshtein DP

Compute the full Levenshtein 2D table between any two words. Recurrence: $$DP[i][j] = \min(DP[i-1][j] + 1,\; DP[i][j-1] + 1,\; DP[i-1][j-1] + \text{cost})$$

3. Trie Traversal with DP Row State & Branch Pruning

Instead of running Levenshtein against all $N$ words ($O(N \cdot M \cdot L)$), we push DP rows down the Trie during Depth-First Search.

Step 1

Root State

Initialize row 0: $[0, 1, 2, \dots, |W|]$ representing the empty prefix.

Step 2

Row Propagation

Child node character $c$ updates the row using only the previous row in $O(|W|)$ time.

Step 3

Subtree Pruning

If $\min(\text{currentRow}) > K$, prune the entire subtree immediately. Over 98% of branches are safely skipped.

Step 4

Candidate Acceptance

If node is terminal and $\text{currentRow}[|W|] \le K$, add candidate and rank by edit distance & frequency.
